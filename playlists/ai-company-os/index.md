# Agentic Engineering Over Loop Rebrands: The Software Factory Playbook

One creator, Dan Eisler (IndyDevDan), defines the early shape of this collection: stop treating “loop engineering” as the insight and instead design AI developer workflows that combine engineers, agents, and code into software factories. His framing is practical and structural—scale compute not engineer effort, keep engineers at the start and end, and treat specialized paths (like production hotfixes) as first-class factory workflows.

## Where They Agree

- Dan Eisler argues loop engineering is a shallow rebrand of the SDLC; the real leverage is AI developer workflows, not the loop label.
- Value creation has three actors—engineers, agents, and code—and Dan calls code the unsung hero of that trio.
- Dan reframes the work as software factory workflows: scale from simple lint loops to sandboxed factories and specialized paths like production hotfixes.
- Engineers belong at the start and end of the workflow; you scale compute, not engineer effort.
- Practical rules Dan emphasizes: keep it simple, separate code from skills, and design workflows by running them yourself first.
- Progression matters—work trees, then full sandboxes—with an agentic layer over the app layer, not vibe coding but meta-engineering.
